# V0.5 : mise en service

Prérequis : V0.4 en place (migrations 0001 à 0005).

## Supabase
1. **SQL Editor** : exécuter `supabase/migrations/0006_v05.sql`.
2. Vérifier : `select proname from pg_proc where proname in ('acquire_job_lock','release_job_lock');` → 2 lignes.
3. Exécuter `supabase/tests/rls_two_accounts.sql` (instructions en tête du fichier) : message attendu « TEST TERMINÉ : tous les contrôles sont OK ».

## GitHub (maintenance planifiée, facultative mais recommandée)
Settings → Secrets and variables → Actions :
| Nom | Type | Valeur |
|---|---|---|
| `SUPABASE_URL` | secret | URL du projet (`https://xxxx.supabase.co`) |
| `SUPABASE_SERVICE_ROLE_KEY` | secret | clé « service_role » (Project Settings → API). **Très sensible : ne la copie jamais ailleurs.** |
| `TELEGRAM_BOT_TOKEN` | secret, facultatif | jeton du bot (via @BotFather) |
| `APP_URL` | variable, facultatif | adresse du site, ajoutée aux messages Telegram |

Sans les deux premiers secrets, la tâche s'arrête proprement (« Tâche ignorée »). Premier essai : Actions → « Maintenance planifiée » → Run workflow, puis page **Journal** de l'application.

## Telegram (facultatif)
1. Créer un bot avec @BotFather, enregistrer son jeton dans `TELEGRAM_BOT_TOKEN`.
2. Écrire un message au bot, puis ouvrir `https://api.telegram.org/bot<jeton>/getUpdates` et relever `chat.id`.
3. Application → Paramètres → Notifications Telegram : activer et saisir l'identifiant.

## Application
Après la fusion, vider l'ancien cache de l'application si besoin. Nouvelles pages : **Statistiques** et **Journal**.
